# Мой трекер

Лёгкий веб-сайт-инструмент для себя: настраиваете, что хотите отслеживать, и ведёте записи с телефона.

**Разделы (включаются и сортируются в настройках):**

- 💶 **Финансы** — расходы и доходы, категории, наличные и свои карты; итоги за неделю/месяц/год, разбивка по категориям и картам.
- 🏋️ **Тренировки** — библиотека из ~170 упражнений и тренажёров, свои упражнения; программы по дням недели и времени (есть шаблоны); экран тренировки с таймером, подходами, таймером отдыха и подсказкой «как в прошлый раз»; рекорды и прогресс.
- 🚬 **Курение** — запись в одно касание, что именно курил, дневной лимит, статистика, покупки пачек сразу в расходы.
- 🛒 **Покупки** — «мой набор» продуктов для дома, список «что купить», оформление чека с ценами → расход в финансах.
- 🩺 **Врачи** — записи к врачам, мои врачи, итоги визитов, стоимость в расходы, выгрузка события в календарь телефона (с напоминаниями).
- ✨ **Свои трекеры** — любые поля: число, деньги, текст, список, да/нет, оценка, длительность; дневная цель «не меньше» или «не больше». 20 заготовок по разделам: **здоровье** (вес, замеры тела, давление, сахар в крови, сон, лекарства, головная боль, настроение), **привычки** (привычка «сделано», вода, шаги, медитация, экранное время, кофе, алкоголь), **занятия** (чтение, учёба, уборка, авто) — и пустая заготовка для своего.

Плюс общий календарь, лента истории, быстрая кнопка «+», светлая/тёмная тема, работа офлайн и установка на домашний экран.

## Где хранятся данные

По умолчанию — только в браузере на устройстве (IndexedDB), ничего никуда не отправляется. Поэтому:
- на разных устройствах данные разные;
- делайте резервную копию: **Настройки → Сохранить резервную копию** (JSON-файл), восстановление — там же.

Если вы поднимете свой сервер (см. ниже), в настройках появится раздел **«Аккаунт»**: записи начнут синхронизироваться между телефоном и компьютером. Приложение при этом остаётся офлайновым — сервер нужен только для обмена, а не для работы.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес из консоли. Чтобы открыть с телефона в той же Wi-Fi сети — используйте адрес `Network: http://192.168.…:5173`.

## Свой сервер: синхронизация и аккаунты

Нужен Docker. Один раз:

```bash
cp .env.example .env
# придумайте пароли MySQL и сгенерируйте ключ шифрования:
#   openssl rand -hex 32   → в ENCRYPTION_KEY
```

### Разработка

```bash
npm run docker:dev      # MySQL + GraphQL-сервер + vite + Mailpit
# или, если фронт вы уже запускаете сами через npm run dev:
npm run docker:api      # только MySQL и сервер
```

- приложение — http://localhost:5173
- GraphQL и GraphiQL — http://localhost:4000/graphql
- письма (подтверждение почты, сброс пароля) — http://localhost:8025

Первая миграция базы: `cd server && npx prisma migrate deploy` (строка подключения — в `DATABASE_URL`).

### Регистрация закрыта по умолчанию

Код приглашения выдаёт владелец сервера:

```bash
cd server && npm run cli -- invite --uses 1 --days 7     # dev
docker compose exec api node dist/cli.js invite          # prod
```

Первый зарегистрированный аккаунт становится администратором — дальше коды можно создавать в приложении
(**Аккаунт → Приглашения**). Чтобы открыть регистрацию всем, поставьте `AUTH_OPEN_REGISTRATION=true` и
настройте `SMTP_URL` (иначе не будет подтверждения почты и сброса пароля).

Другие команды: `user`, `password`, `admin`, `disable`, `list` — см. `npm run cli -- help`.

### Проверка с телефона в домашней сети

Телефон и компьютер — в одной Wi-Fi сети. Узнайте адрес компьютера (`ipconfig` → строка IPv4 у Wi-Fi,
например `192.168.0.54`) и допишите его в `.env` вторым адресом через запятую:

```
APP_ORIGIN=http://localhost:5173,http://192.168.0.54:5173
```

Перезапустите сервер (`docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d api`) и откройте
на телефоне `http://192.168.0.54:5173`. Если страница не открывается — Windows просит разрешить порт в брандмауэре.

Так проверяются вход, двухфакторная проверка, синхронизация и список устройств. **Не** проверяются установка
на домашний экран, работа офлайн и passkeys: браузер считает `http://` по IP небезопасным адресом и эти
возможности отключает. Для них нужен HTTPS — см. ниже.

### Полная проверка: HTTPS

Самый быстрый способ получить HTTPS без домена и VPS — временный туннель к уже запущенному dev-серверу:

```bash
cloudflared tunnel --url http://localhost:5173
```

Команда напечатает адрес вида `https://что-то.trycloudflare.com` — добавьте его в `APP_ORIGIN`
(и в `APP_DOMAIN` без схемы, если хотите проверить passkeys), перезапустите `api` и откройте этот адрес
на телефоне. Туннель открывает дев-сервер в интернет, поэтому пользуйтесь им недолго; регистрация всё
равно закрыта кодом приглашения. Альтернатива для домашней сети без публичного доступа — `tailscale serve`.

Боевой вариант (свой домен) — следующий раздел: там HTTPS выдаёт Caddy, и работает всё, включая passkeys.

### Уведомления на телефон

Сервер умеет присылать push: напоминания про незакрытые цели и превышенные лимиты,
регулярные платежи в день списания, бюджеты на исходе и тренировки с визитами к врачу.
Каждый тип включается отдельным тумблером в **Аккаунт → Уведомления**, настройки общие
для всех устройств, а подписку нужно включить на каждом.

Расписание считает само приложение (оно знает ваши данные и местное время) и присылает
серверу готовый список «когда и что сказать» — сервер только доставляет.

Один раз получите ключи и впишите их в `.env`:

```bash
cd server && npm run cli -- vapid
```

В `VAPID_SUBJECT` укажите свою настоящую почту в виде `mailto:you@example.com` —
без пробелов и угловых скобок, иначе Apple отвечает `403`. Этот адрес уходит в службы
Apple и Google как контакт владельца сервера.

**Требования:** https и зарегистрированный service worker. На iPhone уведомления работают
только для приложения, добавленного на экран «Домой» (iOS 16.4+), и разрешение запрашивается
строго по нажатию кнопки. В обычной вкладке Safari подписаться нельзя.

Service worker подключается только в собранной версии, поэтому проверять уведомления
нужно на ней — dev-сервер для этого не подходит:

```bash
npm run build && npm run preview     # собранная версия на 4173, /graphql проксируется
cloudflared tunnel --url http://localhost:4173
```

Полученный `https://…trycloudflare.com` допишите в `APP_ORIGIN`, перезапустите `api`,
откройте адрес на телефоне, добавьте на экран «Домой», запустите с иконки и включите
тумблер в разделе «Уведомления». Кнопка **«Прислать проверочное»** покажет, что всё дошло.

### Боевой запуск

```bash
# в .env: APP_DOMAIN=tracker.example.com, APP_ORIGIN=https://tracker.example.com, ACME_EMAIL=...
npm run docker:prod
```

Caddy сам получит сертификат Let's Encrypt и будет раздавать `dist/` на `/`, а GraphQL — на `/graphql`
(один домен, поэтому cookie сессии не уезжают на сторонние сайты). MySQL и сервер наружу портов не открывают.

Безопасность аккаунта: пароль (argon2id), сессии в httpOnly-cookie с журналом устройств, двухфакторная
проверка по TOTP с кодами восстановления, вход по Face ID / отпечатку (passkeys), защита от перебора.

### Резервные копии базы

Контейнер `backup` каждую ночь делает `mysqldump` в папку `backups/` и хранит копии 14 дней
(время и срок — `BACKUP_AT`, `BACKUP_KEEP_DAYS`). Восстановление проверяйте на отдельной базе, а не на боевой:

```bash
gunzip -c backups/lifeboard-ГГГГММДД-ЧЧММСС.sql.gz |   docker compose exec -T mysql mysql -u root -p"$MYSQL_ROOT_PASSWORD" lifeboard_restore
```

Данные MySQL лежат в именованном volume `lifeboard_mysql-data` и переживают пересоздание контейнеров.
`docker compose down -v` удаляет их вместе с volume — так делать не нужно.

## Публикация без сервера

```bash
npm run build
```

Папка `dist/` — готовый статичный сайт. Её можно выложить на любой хостинг статики (GitHub Pages, Netlify, Cloudflare Pages, Vercel). Для установки на телефон и работы офлайн нужен HTTPS (все перечисленные хостинги дают его бесплатно).

На телефоне: откройте сайт → iPhone: «Поделиться» → «На экран «Домой»; Android: меню → «Установить приложение».
